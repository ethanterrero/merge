# Member Status Implementation Plan (M-56)

**Goal:** `profiles.suspended_at` / `vetted_at` (server-only), `is_active`, `is_vetted`, `public_name`, and suspension withdrawing a member's invitations, connections, Crews and future rides, in `supabase/migrations/0011_member_status.sql` with `supabase/tests/member_status_test.sql`.

**Spec:** `docs/superpowers/specs/2026-10-08-member-status-design.md`. Decisions: D-06, D-07 (Decided 2026-10-08).

**Base:** `origin/main` at `d3888b2` (migrations 0001–0005, 0008, 0009; hosted at 0009). M-17a builds 0010 in parallel; no dependency.

## Constraints

- Migration 0011 only. No app changes; `database.types.ts` is regenerated by the owner after the hosted push.
- Every `security definer` function: `set search_path = ''`, schema-qualified names, execute revoked from `public`, `anon`, `authenticated` unless clients call it. No extension objects are used.
- `is_blocked` (0005), `is_active` and `is_vetted` aren't client-executable; later client-called RPCs that filter on them must be `security definer`.
- No function from an earlier migration is replaced, so nothing is copied forward.
